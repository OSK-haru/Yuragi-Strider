## 変更前後

| 論点 | 変更前の文書 | 今回の更新 |
| --- | --- | --- |
| 攻撃目的 | 情報取得と干渉を区別するが、主要目的が一覧化されていなかった | 結果への干渉・改ざん、処理内容の推定、埋め込まれた秘密の推定を明記 |
| 共通化の対象 | 共通ワークスペース＋仮想共有QPUという説明が中心 | サービスごとの能力・制約を表す基盤を中心にし、万能な権限を仮定しない |
| 検討順序 | 「まず一課題として決める」を先頭に配置 | 共通フローの仮案→異なる課題例で検証→状態・時間・権限の具体化→最小実装の選定 |
| 共通体験 | 上位設定と課題画面の二階層が中心 | 手動／プリセット→攻撃側→調査・操作→実行・観測→分析・反復→個別判定を追加 |
| 攻撃操作 | 自分のジョブ送信に偏った構造図 | ジョブを操作要求の一種とし、計測・部品編集等は追加のアクセス条件として候補化 |
| 設定の意味 | 被害者・サービス・演習を主に列挙 | 装置・サービス・被害者・攻撃者・課題の五区分案を提示。画面・スキーマは未決定 |
| 観測と成否 | 一般的な情報境界の説明 | キュー情報／被害者識別／実行時刻、被害発生／攻撃者の確認／判定器の評価を分離 |
| 情報漏洩の経路 | 共有資源→自分の測定を主に記述 | 自分の測定、許可された計測、被害者アプリの公開出力を区別。被害者結果の自動転送は置かない |
| 現実性の根拠 | サービス資料・論文へのリンクを中心に列挙 | 物理実証、アクセス可能性、条件の同時成立を分け、対象・時点・追加仮定を残す案を追加 |
| 文献の位置付け | クロストーク等の題材候補 | 六つの研究を目的・操作・仮定へ対応付け、QubitHammerのタイミング・校正条件等を明記 |
| 進捗 | 一課題の具体化を次の着手条件として記載 | 共通フロー案とサービス差の整理が進展。攻撃モードの実装・検証は進んでいないことを維持 |

## 維持した方針

- 上位の設定画面と、課題中の攻撃側画面という二階層。
- 独立した高機能な攻撃者環境と、共通基盤へのプリセット適用。
- 自由実験と提出演習を別製品・別実行基盤にしない。
- 量子固有の因果関係の理解を中心にし、量子暗号は対象外。
- 古典的準備を省略しても、その開始条件を明示する。
- 物理基準版 `699a110` / `yuragi-strider-physical-baseline-v1` は変更しない。

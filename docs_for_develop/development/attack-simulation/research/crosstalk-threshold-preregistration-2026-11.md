# 事前登録: パルスアクセスによる駆動クロストーク閾値の低下

作成: 2026-11-08（草案、未承認）。実験の前に問い・指標・判定基準・予測を固定するための文書である。
実験を始めた後にこの文書の判定基準を変える場合は、変更点と理由を末尾の変更履歴に残す。

## 1. 問い

共有の超伝導量子計算機で、隣の領域に住む攻撃者が駆動クロストークを使って被害者の計算を壊すとき、
被害者の成功率を有意に下げるのに必要な漏れ強度 ε の最小値（閾値 ε*）は、攻撃者がどこまで制御できるかで
どれだけ変わるか。

- **ゲートレベル攻撃者**: 校正済みゲート（X）しか打てない。ドライブは攻撃者自身の量子ビットの周波数で、
  被害者から見た離調 Δ は量子ビット間の周波数差に固定される。
- **パルスレベル攻撃者**: ドライブ周波数を変えられる。事業者が許す周波数シフトの幅を W とすると、
  被害者から見た離調は max(Δ − W, 0) まで下げられる。

副問い1: 事業者が W をどこまで絞れば、現実的な ε（下記）で攻撃が成立しなくなるか。

副問い2（経路の分離）: 量子ビット間には制御線の漏れ ε のほかに、静的な結合 J がある。攻撃者が自分の線を被害者の周波数で
駆動すると、J を介した cross-resonance 的な効果も生じる。QubitHammer 型の攻撃の効果は、どちらの経路から来ているのか。
ε = 0 でも J だけで攻撃は成立するか。

## 2. 先行研究と新規性の主張

調査日 2026-11-08（WebSearch。本文未読の論文は要旨のみで判断）。

- Ash-Saki, Alam, Ghosh, ISLPED 2020: multi-programming でのクロストークによる故障注入。ゲートレベル、実機。
- Tan, Choudhury, Basu, Szefer, "QubitHammer", arXiv:2504.07875: 被害者の共鳴周波数のパルスで
  Grover などを壊す（実機、TVD 最大 0.938）。**ε の数値も ε を振った閾値解析もない。**
- Shubha & Farheen, arXiv:2507.16181（QCE 2025 workshop）/ arXiv:2509.11407: パルスレベルの
  シミュレーション。前者はユニタリ・規格化パラメータで閾値なし。後者は本文未読。
- 実測の駆動クロストーク: Kosen et al., arXiv:2403.00285 で平均 −39.4 dB（振幅比 約1%）、
  範囲 −56〜−27 dB（0.16%〜4.5%）。

主張する新規性（シミュレーション上の定量化に限る）:
同じ物理モデルの中で、ε を実測範囲にまたがって掃引し、ゲートレベル攻撃者とパルスレベル攻撃者の閾値 ε* を求め、
周波数シフト幅 W の関数として閾値がどう動くかを示す。実機で攻撃が成立することは主張しない。

主張を崩しうるもの（実験前に確認する）:
1. 2509.11407 の本文に同じ閾値解析がある。
2. 2025年後半以降の新しい論文。投稿や公開の前に arXiv を再検索する。
3. キックモデルの誤差が、閾値付近で結論を変えるほど大きい（§5）。

## 3. 実験設計

モデルは2段に分ける。必要に応じて物理モデルを拡張してよい（ユーザー了承、2026-11-08）。

- **段A（製品のキックモデル）**: 4量子ビットの Grover 全体で ε と離調を掃引する。速いが、2準位で、J は含まない。主問いと副問い1に使う。
- **段B（参照のパルスモデル）**: `core/pulse_transmon_network.py` と `core/experimental_isolation_physics/coherent_crosstalk.py` の
  結合トランズモン網（1〜4個、3準位、交換結合 J、残留 ZZ、駆動クロストーク、Lindblad 散逸）。
  攻撃者1個と被害者1〜3個で、ε と J を独立に振る。段Aの検証（§5）と副問い2に使う。
  被害者の回路は、パルスで書ける範囲（単一量子ビットのゲート列と、可能なら2量子ビットの Grover）に限る。
  2量子ビットゲートをパルスで組めるかは2日目に確認し、組めない場合は理想ゲートを挟む近似と明記する。

### 段A

基盤は製品の free mode（`tenant_dedicated_region` / `overlap_disjoint_regions`）。
`scripts/experiment_crosstalk_grover.py` と同じ組み方をする。

- **被害者**: 4量子ビット、2反復の Grover、marked `1011`。50 shots × 8 jobs = 400 shots
  （命令数上限のため1 jobあたり最大59 shots）。
- **攻撃者**: 被害者の領域に隣接する量子ビットで X パルスを連続して打つ（被害者の時間窓を覆う）。
  ゲートレベル攻撃者とパルスレベル攻撃者の違いは離調だけで表す。パルスの形状・振幅・長さは同じにする。
- **ε の格子**: 0.0005, 0.001, 0.002, 0.005, 0.01, 0.02, 0.05, 0.1, 0.3（対数間隔、約 −66〜−10 dB）。
- **実効離調の格子**: 0, 1, 3, 10, 30, 100, 300 MHz。
- **漏れの向き**: 攻撃者から被害者への一方向（`attacker_to_victim`）。
- **乱数**: 各条件で job キーを変えた3系列。系列ごとの値と、合算した値の両方を出す。
- **計時**: 時計を止めた宣言実行（`DeclaredQpuExecutor`）。ブラウザやネットワークの揺らぎは扱わない。

離調は `qpu_service.runtime_execution.drive_crosstalk_detuning_mhz` で選ぶ（D84、2026-11-08 実装。既定は 100 MHz のサンプル値）。
パイロットは、この設定を入れる前に、スクリプトの中からモジュール定数を差し替えて回した。

### 段B

- 攻撃者のドライブ: 被害者の周波数で連続して駆動する（パルスレベル攻撃者）か、自分の周波数で X 列を打つ（ゲートレベル攻撃者）。
- 格子: ε ∈ {0, 0.001, 0.003, 0.01, 0.03}、J/2π ∈ {0, 0.5, 1, 2, 5} MHz、量子ビット間の離調 {100, 300} MHz。
  J と離調は、固定周波数トランズモンでよく使われる範囲から取った仮定値として明記する。
- 出力: 被害者の忠実度（または成功率）、被害者の第3準位の占有、攻撃者との相関（相互情報量）。

## 4. 指標と判定基準

- **主指標**: 被害者の成功率 p（marked を得た割合）。攻撃なしの p₀ と比べる。
- **「有意に下げた」の定義**: 製品の採点と同じく、p₀ − p ≥ 0.15 かつ 3σ を超えること
  （σ は二項分布、p₀ と p の差の標準誤差）。
- **閾値 ε*(Δ)**: 上の条件を満たす最小の ε。格子上の値で報告し、隣り合う2点の間を対数で線形補間した値も添える。
- **閾値比**: R = ε*(Δ=100 MHz) / ε*(Δ=0)。

## 5. 検証

- キックモデル（Magnus 展開の2次、2準位）を、段Bの J = 0 の場合として`scripts/experiment_kick_vs_pulse_network.py` の
  パルスレベルのネットワーク計算と比べる。対象は閾値付近の (ε, Δ) 少なくとも6点で、Δ = 0, 1, 3, 100 MHz を含める。
- 誤差の許容値: 被害者の成功率の差が、その条件の 1σ 未満であること。超えた場合は、その Δ 帯の閾値を
  「モデル誤差により未確定」と報告する。

## 6. 予測（実験前に固定）

考え方: 共鳴（Δ=0）では漏れは1次で効き、回転角はおよそ εΩT（Ω は X のラビ周波数、T はショット長）になる。
大きく離調すると1次の寄与は振動して打ち消し合い、残るのはおよそ ε²Ω²T/Δ の AC シュタルク的な回転になる。

- **H1**: ε*(0) ≤ 0.005。パイロット: 0.5% で成功率が 0.72 から 0.14 に落ちた（50 shots）。
- **H2**: R ≥ 10。
- **H3**: ε*(Δ) は Δ が大きいところで、おおよそ √Δ に比例して増える（傾き 0.5 ± 0.2、対数-対数）。
- **H4**: 現実的な範囲（ε ≤ 0.045）で Δ = 100 MHz のゲートレベル攻撃は成立しない。
- **H5**: ε = 0 でも、J/2π ≥ 1 MHz なら、被害者の周波数で駆動するパルスレベル攻撃は被害者を有意に乱す（J 経路だけで成立する）。

外れても、結果は結果として報告する。

## 7. モデルの限界（報告に必ず書く）

- 段Aの漏れは古典的な駆動クロストークだけで、キックは2準位の回転。J による効果と第3準位へのリーケージは段Bでだけ扱う。
- 段Bは最大4トランズモンで、被害者の回路は小さい。段Aと段Bの結論をつなぐときは、その外挿を明記する。
- 段Bの J と量子ビット間の離調は仮定値で、どの実機の値でもない。
- パルス形状（σ = 長さ/4 のガウシアン）と離調は宣言値で、どの実機の測定値でもない。
- 実在の事業者が許す周波数シフト幅は調べていない。W は仮定のパラメータとして扱う。
- 待機ノイズは校正値（ibm_kingston、2026-04-15 の snapshot）。

# 局所物理近似の共通契約案

状態: **一部合意・全体は提案中**。共通QPU基盤の切出し・状態保持・検証の構造案。領域選択の原則と非対応構成の事前拒否は合意済みだが、数値上限、誤差基準、実装schemaは確定しない。

最終更新: 2026-10-01。

## 1. 対象と不変条件

自由・課題モードが共有するQPU物理基盤を対象とする。大規模QPUは量子ビット、結線、制御系、読出し系、割当、仮想時刻のメタデータとして保持し、状態計算は一つの処理に関係する範囲へ限定する。回路入力上限8量子ビットは、周辺量子ビットを含む物理計算領域の上限ではない。

近似は「状態のどの情報を捨てたか」と「何を正しいと主張するか」を組にして定義する。標的1量子ビットの`P(1)`だけを合わせても、共同観測、後続ジョブ、攻撃判定が保たれたことにはしない。既存の[実行境界方針](runtime-boundaries-and-resolutions.md#2-閉じた局所実行領域)に従い、意味を変える切断や未検証の遠方影響を黙って近似へ混ぜない。

### 合意済みの原則

- 計算領域は、対象eventの時間窓で有効な影響関係に加え、状態保存機が引き継いだ過去の相関・未解消の状態依存を根拠に選ぶ。
- 必要な相関を許可済み近似で保持できず、資源上限も超える構成は、実行開始前のpreflightで非対応として拒否する。実行中に相関を黙って切り捨てて続行しない。

この合意は規則の方向を決めたもの。どの相関が「必要」かをobservable・後続操作・課題判定に結びつける方法、境界近似の許可条件、資源上限はまだ定義・検証が必要。

## 2. トポロジーは異種の関係として表す

一枚の量子ビット隣接グラフだけでは、攻撃・干渉経路を選べない。各関係は、機構、端点、強さ・確率、適用時間、由来、適用条件を持つ別の辺またはハイパー辺として扱う。

| 関係 | 接続するもの | 計算領域に必要になる情報 |
|---|---|---|
| 量子相互作用 | 操作可能なゲート接続、交換結合、残留ZZ | 適用中の操作、結合係数、位相・コヒーレンス、過去に作られた相関 |
| 制御伝達 | 制御線・駆動源から標的／周辺量子ビット | パルスの時間窓、振幅・位相の伝達、同時に駆動される対象 |
| 読出し共有 | 共振器、読出し線、分類器などの共有グループ | 同時に読む真のbit列と共同分類誤差。量子状態の測定後更新と返却countsを分ける |
| 時間的状態継承 | 同じ物理量子ビット上の連続event・tenant割当 | 先行状態、Reset／待機／測定event、実行順と装置時刻 |

辺は「トポロジー上で近い」だけでは有効化しない。サービスprofileとevent scheduleが、その関係をいつ・誰に対して有効にするかを示す。逆に、長距離制御漏れや共有読出し群は近傍hop数だけで切れない。

## 3. 計算領域の選択

1. その時間窓で実行・観測される被害者／攻撃者の量子ビットと共有装置要素を起点にする。
2. 時間窓内で有効な機構別の関係をたどり、出力に影響し得る周辺要素を加える。
3. 現在の結合だけでなく、状態保存機が持つ過去の相関・未解消の状態依存も含める。相互作用を止めても、すでに作られたもつれや相関が自動で消えるとは扱わない。
4. 必要な状態・観測を含む領域が資源上限を超える場合、許可済みの境界近似がなければ開始前のpreflightで拒否する（原則合意済み）。

切出し距離や係数の閾値は未決定。係数が小さいという理由だけでedgeを落とさない。係数ゼロ、profile上の明示的な不在、または対象observableに影響しないことを検証した境界だけを切断候補にできる。全体が一つの大きな連結領域になる構成を無理に分割するより、実行前に非対応とする。

## 4. 状態表現と境界の扱い

状態表現は、後続jobが要求する操作・観測を実行できなければならない。同じ物理状態の正本を複数の独立計算が持たない。

- **結合領域:** 相関を必要とする量子ビットを一つの局所状態として進め、物理eventごとに共有状態へ反映する。
- **厳密に分離できる領域:** 初期状態と操作から独立性が成立すると確認できた場合だけ別々に保持する。
- **検証済み縮約:** 縮約状態が保つobservable、初期状態、操作列、時間範囲を明記する。将来の操作に必要な情報を捨てるなら、永続状態の更新には使わない。
- **扱えない境界:** 結合計算へ戻せず、必要な相関も保てない場合は開始前に拒否する。黙って平均場化・独立誤差化しない。

現在の条件付きブロック法は、周辺量子ビットに横駆動・交換結合がない限定系で、標的`P(1)`を求める探索手段として有望だった。しかし周辺量子ビットの非対角コヒーレンスを捨てるため、一般の後続操作に使える正本状態ではない。初期重ね合わせを含むケースで標的`P(1)`が一致した事実を、状態全体の一致へ拡張しない（[探索記録](progress.md)）。

## 5. 機構ごとの主張と必要な比較

| 機構 | 捨てると問題になる情報 | 最低限比較する出力 |
|---|---|---|
| ZZ・交換結合 | 条件付き位相、量子ビット間コヒーレンス、共同相関 | 位相を読む基底を含む共同分布、後続ゲート後の分布 |
| 制御クロストーク | 伝達先の駆動振幅・位相と時間重なり | 標的・周辺の同時出力、周辺駆動有無の対照 |
| 相関Readout | 真値bit間の共同誤分類 | 全共同counts分布。独立Readout近似との比較 |
| Reset・時間的再利用 | tenant交代前の状態、Reset後の残留、event順序 | Reset後と待機後の測定、複数job列の観測・状態 |

機構単独の検証を通っても、重なった機構の合成を自動的に対応済みとしない。結合計算を参照にする場合、同一の初期状態・event時刻・設定を使い、対象領域が小さいうちに比較する。

## 6. 近似を採用する検証条件

各近似methodには、少なくとも次を対応づける。

- 対応する関係種、初期状態、操作・時間窓、準位、雑音モデル。
- 保存する状態情報と、明示的に捨てる相関。
- 正しさを主張するobservableと、その観測方法。
- 小規模結合参照計算との比較結果、試験条件、method版。
- setup／compile時間、物理計算時間、ピークmemory。仮想装置時間とhost処理時間は別に測る。

比較は次の段階で行う。

1. 単一機構について、基底・重ね合わせ・相関のある初期状態、係数、時間、駆動、雑音条件を振る。
2. 同一状態を次jobへ渡し、複数job列と複数観測基底で誤差を測る。
3. 当該課題で攻撃者が取得する共同counts、秘密推定量、hidden判定への影響を比較する。
4. 計算領域・event・job数を増やして性能を測り、実行前見積りが上限超過を検出することを確かめる。

採否は単一の`P(1)`誤差で決めない。分布差、状態を使い回した場合の差、攻撃成功・失敗の反転、計算資源を合わせて記録する。数値許容値と信頼水準は、課題ごとの評価規則と実測後に決める。評価閾値付近で近似誤差が合否を反転させる条件は、根拠ある誤差境界や不確かさ処理を導入できるまで対応範囲に含めない。

## 7. 実行計画と失敗の意味

既知の予定eventがあるscenarioでは開始前に、設定・予定event・observableから`ApproximationPlan`相当の計画を確定する。自由モードなどで後から届くjobは、その時点の正本状態・予約済みwindowと合わせて物理実行前に検査し、必要なら計画を更新する。少なくとも選択領域、methodと版、必要能力、前提、捨てる情報、対象出力、計算量見積り、検証根拠を追跡できること。相関保持不能または資源上限超過で安全に実行できない場合はpreflightで拒否する。これは設計上の情報要件であり、型名や永続schemaの確定ではない。

同じ計画で処理できるshotごとに高価な適用可能性探索を繰り返さない。新しいjobや同時windowの変更があれば、影響する範囲を物理実行前に再検査する。実行時状態が前提から外れた場合は誤った近似を続けず、試行を「物理計算失敗／非対応」として止め、攻撃者の失敗やgrader不合格へ変換しない。利用者向け表示には内部状態・秘密を含めない。

## 8. 現在の証拠と未決定

2026-09-30の探索は主に二量子ビットの物理計算と合成条件であり、複数機構・状態継承・攻撃判定・100量子ビット級の実runtime性能を一括検証したものではない。条件付きブロック法の約1.7～2.7倍はsolver部分だけの値で、サービス全体の高速化ではない。当時の単一量子ビットruntimeは後続の共通Programで複数qubitへ拡張し、D57/D58後続では全体topology metadataと固定局所state bindingを追加した。一方、動的領域選択・必要相関に応じた切出しとactive physics接続は未実装。局所領域計算の方針は合意済みだが、本書の切出し・状態表現・比較条件は**提案中**である。[最新の実装証拠](progress.md)を参照。

次に詰めるのは、(a) 必要相関をobservable・後続操作・課題判定から特定する規則、(b) 境界を越えて保持する状態情報と表現変換条件、(c) 最初に受け入れるobservableと課題判定、(d) 検証後の物理計算・host資源上限。先に代表的な小規模job列を選び、この案で切出しと失敗条件を具体的に追えるか確認する。

Reset、同時駆動クロストーク、相関Readoutに同じ選択原則を当てた[三事例点検](local-physics-three-case-design-check.md)を実施した。機構によって共有すべき対象は量子状態・制御信号・報告値と異なるため、関係辺の連結性だけで共同密度行列の要否を決めない。自由モードの未知の将来ジョブ、複数領域のmerge/split、共同window、読出し後の状態更新は引き続き設計課題である。

## 確定した操作階層

課題中は攻撃側画面のみ操作でき、実機側・被害者側は上位のシミュレーター設定で扱う。
CTF型プリセットには攻撃者・被害者・実機側設定を割り当てる。量子暗号は今回の対象外。
この方針自体は未決定事項から外し、以下では実装契約と具体的な課題内容を決める。
環境管理者はメタ層、参加者資格情報発行はサービス層へ置き、両modeで管理者設定を開始前だけ変更可能とする（D52）。フォールバックは要求の競合・重複実行を防ぐ復旧再開とする（D51）。責務配置とこの方向は未決定から外すが、認証方式・復旧手順まで確定した意味ではない。

時間接続の追加判断: 宣言待機へ物理作用を適用する方向（D54）は維持。D72で製品はhost_clock 1xに固定し、成立前のcatch-up pauseを選択可能にした。explicit_waitは内部試験のみ。queue／通信／compile／公開・被害者動作のservice-time根拠と性能基準は未承認提案として残り、Q02/Q04と合わせて[実サービスとの対応](service-time-and-workload-comparison.md)を見直す。固定周期だけの被害者は採用しない。

D56で依存方向を共通契約→サービス／物理profile・被害者workload→課題presetと明示した。Q07の共通時間契約をQ01の課題選択へ従属させない。被害者はいつ・何に・どの共通操作を行うかを設定できる構造とし、Q04にはその正式schema・具体的な操作列が残る。初期化方針もservice／Program契約で扱い、Reset課題だけの特例にしない。[所有境界と残る内部adapter](architecture.md#共通契約と課題設定の依存方向2026-10-04)を参照。

## 検討順序の更新

閉鎖有限sourceと`LiveWorkloadWorld`のlive受付・有限source・取消／照会・物理event・releaseは接続済み。D61 owner lifecycle、factory、設定resolver、desktop／development mount、host-clock WebSocket/UIも実装済み。残件は公開proxy運用・process間共有／restart recovery、Reset課題の製品preset／採点接続など。HTTP polling候補はWebSocket接続後も暫定候補として機能追加を止め、削除は別途判断する。実所有認証では秘密情報処理等の承認境界を守る。

大規模実装前の五判断はD57で[共通基盤v1の暫定契約](common-foundation-v1-contract-proposal.md)へ昇格した。D57の初期1倍は履歴であり、live時計はD60の明示policyへ更新済み。単発・事前job群・結果依存workload、共通状態継承、実公開Webのserver正本／ブラウザ所有session、ページ再読み込み／同一process内の整合復旧は採否待ちから外す。server再起動復元は後続へ分けた。D58の複数qubit・全体トポロジーと局所計算の分離を実装時に検査する。正式schema・同期方式・計測上限値を、全てユーザーの判断待ちにしない。

D55で、共通構造から対象範囲を限定して現実サービスへの特殊化可能性を示す方針を採用した。Q02/Q06/Q07に対する[定義・確認義務・対応案](service-specialization-contract.md)は文書化済みだが、正式schema、方針意味論の完全定義、形式的な確認は未完了。個別サービス実装や全サービスの対応完了を、初回体験の着手条件へ自動追加しない。

## 画面のスクリプト実行の残件

2026-10-14に実装した[画面のスクリプト実行](script-access.md#画面のスクリプト実行疑似シェル)で、利用者の判断が要るもの。

- **追加パッケージの入手先**: numpy 等は公式CDNから読む（lock の SHA-256 で検査）。デスクトップ版をオフラインでも使うなら、必要なwheel（numpy は約3MB）を配布物に同梱する。同梱すると配布物が大きくなり、同梱するパッケージを選ぶ必要がある。
- **公開デモでの扱い**: 公開デモの配信（`frontend/src/worker.ts`）は COEP を付けていないため、スクリプト実行は使えない（理由を出して止まる）。使えるようにするには、配信に COOP/COEP と Python 実行用パスの CSP を足す。8/31以降の変更は公開しない規則があるため、時期は公開の再開と合わせて決める。
- **実行時間とメモリの上限**: 今は利用者が止めるまで動く（Ctrl+C、3秒後に Worker ごと停止）。ブラウザのタブの中だけで完結するのでサーバーには影響しないが、自動の上限を設けるかは未定。

## 共有QPUの計算速度（後回し）

2026-10-14の計測で、交互観測1ジョブ（32 rounds、6 qubit 保持）の計算約0.31秒のうち約6割が、イベントを記録するたびに密度行列（64×64）を Python の tuple の入れ子へ作り直す処理（`core/attack_simulation/qpu_state.py` の `_immutable_density_matrix`）だった。物理計算そのものではない。

- **利用者の決定**: Python のまま表現を作り直すのは無駄なので行わない。後で Rust 化するときに着手する。その際は、PyO3 で Python と Rust の間を変換する計算量と、Rust 化で得られる高速化量のトレードオフを見て、どこまでを Rust 側へ移すかを決める。
- **当面の対処**: 課題のプリセットは保持する qubit を絞る（自由モードは制限しない）。

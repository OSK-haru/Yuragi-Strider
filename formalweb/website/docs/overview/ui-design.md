# 画面表示の設計方針

Yuragi-Striderの画面は、体験としての見た目と、研究用途でもデータを正しく読めることの両方を狙っています。見た目の方針がデータの読みやすさとぶつかる場合は、**読みやすさを優先**します。このページでは、画面の色・文字・操作の決まりと、その根拠を示します。

シミュレーター本体の画面には、こうした根拠の説明を載せていません。画面をデータを読むことに集中させるためで、説明はこのページに集めています。

## 色の役割

### 赤は警告のための色

赤(アクセント色)は**警告・エラー・取り消せない操作(削除など)・危険表示**に限って使います。ホバー・選択中・現在地といった操作状態は、赤ではなく**白黒の反転**で示します。

すべてを赤で強調すると、本当の警告が目立たなくなるためです。赤を異常・危険に割り当てる考え方は、IEC 60073(表示器の色の意味)や ISO 9241 の色の使い方と同じです。

### データの色はブランドの色と分ける

行列の要素の符号や位相といった**データの値は、赤一色では表しません**。正負は赤と青で、位相は複数の色を使う循環ランプで表します(下記)。

## データの色分け

### 正負(実部・虚部)

すべての画面で同じ割り当てを使います。

| 値 | 色 |
|---|---|
| 正 | 赤 |
| 負 | 青 |
| 絶対値(符号なし) | 文字色(ダークテーマでは白、ライトテーマでは黒) |

Gate-awareの状態エクスプローラーと、Pulse状態エクスプローラーの密度行列は、どちらもこの割り当てです。色の濃さは値の大きさを表します。

### 位相

位相は $-\pi$ と $+\pi$ が同じ値になる**循環量**です。赤から白へ一直線に変わる色で塗ると、ほとんど同じ位相(たとえば $3.1$ と $-3.1$、差は約 $0.083$ rad)が両端の最も違う色になってしまいます。

そこでYuragi-Striderでは、一周すると元の色に戻る**循環ランプ**を使います。

| 位相 | 色 |
|---|---|
| $0$ | 文字色 |
| $+\pi/2$ | 橙 |
| $\pm\pi$ | 赤 |
| $-\pi/2$ | 青 |

色は8段に分けてあり、$\pm\pi$ は同じ段に入ります。色の濃さは要素の絶対値です。正確な値は、セルにカーソルを合わせるかフォーカスすると表示されます。

### 選択中の要素

行列の中で選んだ要素は、**文字色の外枠と背景色の内枠からなる二重枠**で示します。正の値を赤で塗るため、赤い枠だと赤いセルの上で見えなくなるからです。

## 文字と読みやすさ

Webコンテンツのアクセシビリティの国際的な指針 WCAG 2.2(日本では JIS X 8341-3)の適合レベルAAを基準にしています。

- **コントラスト比**:本文と小さな文字は背景に対して $4.5:1$ 以上、大きな文字と操作部品の輪郭は $3:1$ 以上にしています。赤い文字には、暗い背景でもこの基準を満たす専用の赤を使っています。
- **文字の大きさ**:最小を 0.68rem(標準設定で約11px)にしています。
- **言語の指定**:画面の言語を日本語として宣言しています。読み上げソフトが日本語として読むためです。

## 操作

- **フォーカス表示**:キーボードで操作しているときは、フォーカスのある部品に太い枠を表示します(WCAG 2.4.7)。
- **閉じたメニュー**:閉じているメニューの項目にはフォーカスが移らないようにしています。見えない場所にフォーカスが入るのを防ぐためです。
- **動きを減らす設定**:OSで「視差効果を減らす」などの設定が有効な場合、アニメーションを止めるか減らします。

## 結果ファイルの記録

結果を書き出したファイルには、入力一式に加えて、**書き出したアプリのビルド識別子**(コミットの短縮ハッシュ)を記録します。どのバージョンで計算した結果かを、あとから辿れるようにするためです。未コミットの変更を含むビルドでは、識別子の末尾に `-dirty` が付きます。

# 実機比較

実際の量子プロセッサで測定した観測量と、Yuragi-Striderのモデル予測を比較した記録です。

:::danger[形式的な合格判定は確立していません]
このページで扱う実機比較は、事前登録したプロトコルに基づく**形式的な合格判定に到達していません**。判定は「候補段階」であり、形式監査ではありません。

Yuragi-Striderを校正済みハードウェア予測器として扱うことはできません。

以下では、実施した条件・両者に与えた入力・得られた数値・**未達成の理由**をすべて記載します。
:::

---

## 1. 実施条件

### ハードウェア

```text
プロバイダ    : IBM Quantum
バックエンド  : ibm_kingston(version 1.0.0)
物理量子ビット : 150
ネイティブ dt : 4 ns
読み出し      : 計算基底Z測定、同一ジョブ内で読み出し校正
```

これは**実機のデータ**であり、シミュレーターの出力ではありません。生の実行結果はジョブIDとともに `validation_hardware/raw/` に保存されています。

データセット登録簿では、シミュレーション由来のデータセットは「実機観測ではない」として明示的に**却下**しています。

### 測定回路

| 実験 | 回路 |
|---|---|
| 読み出し校正 | $\lvert0\rangle \to M$ および $X \to M$(同一ジョブ内) |
| $T_1$ | $X \to \text{delay}(t) \to M$ |
| Ramsey | $H \to \text{delay}(t) \to H \to M$ |
| スピンエコー | $H \to \text{delay}(t/2) \to X \to \text{delay}(t/2) \to H \to M$ |

遅延グリッドは **0, 20, 40, …, 400 μs の21点**(バックエンドの dt 単位で指定)です。回路は物理量子ビット150に固定して転送し、最適化レベル 0 で転送後も割り当てが動いていないことを確認しています。

### 比較の全体設計

実機とシミュレーターは「同じ量」を出せません。実機が返すのは**測定ショットのカウント**、シミュレーターが返すのは**密度行列**です。したがって次の対応で突き合わせます。

| 項目 | 実機側に入力したもの / 得たもの | Yuragi-Strider側に入力したもの / 得たもの | 対応 |
|---|---|---|---|
| 回路 | 上表の回路をネイティブゲートへ転送して投入 | 同じ回路構造(ゲート列 + 待機区間)を指定 | 論理的に同一の操作列 |
| 遅延時間 | dt 単位の `delay` 命令 | 同じ長さの待機区間 | 数値として同一 |
| 環境 | デバイス自身の物理特性(制御不能) | デバイス校正値から換算したレートを入力 | **実機の測定値をモデルの入力に写す**(モデル側を実測に合わせる方向) |
| 測定 | 1回路あたり 1,024 ショットの計算基底測定 | 密度行列の対角成分 $\rho_{11}$ | 実機側をアフィン読み出し補正して確率に直す |
| 読み出し誤差 | 実測に含まれる | モデルは含まない | 実機側の補正で吸収する |
| 比較量 | 補正後の $P(1)$ | $\rho_{11}$ | 同一の遅延点で1対1に対応 |

:::info[モデルは実機に合わせて調整していません]
環境レート(コヒーレンス時間)だけはデバイスの校正値を入力として与えていますが、**測定結果を見てからパラメータを再調整する(再フィットする)ことは一切していません**。再フィットすれば見かけ上の一致は改善しますが、それは予測能力の検証になりません。すべての実行で再フィットなしを記録しています。
:::

### 事前登録した合格条件

```text
形式判定に必要なショット数 : 各回路 1024 以上
解析手順(固定)          :
  1. アフィン読み出し補正
  2. T1 減衰フィット
  3. 減衰振動Ramseyフィット
  4. 両方が有効な場合のみ 1/Tφ = 1/T2 − 1/(2T1)
  5. ショット再標本化によるブートストラップ信頼区間

PASS の条件 :

  95% 信頼区間に含まれること
  かつパラメータ整合性 95%
  かつ再フィットを行わないこと
```

## 2. 読み出し校正

### 数式

読み出しには誤り確率があるため、観測された「1」の頻度は真の励起確率とずれます。準備状態が既知の2回路から、アフィンな関係を求めます。

$$
p_{\text{obs}} = p_{10} + \left(p_{11} - p_{10}\right)P_1^{\text{true}}
\quad\Longrightarrow\quad
P_1^{\text{corr}} = \frac{p_{\text{obs}} - p_{10}}{p_{11} - p_{10}}
$$

ここで $p_{10} = P(\text{観測}1 \mid \text{準備}0)$、$p_{11} = P(\text{観測}1 \mid \text{準備}1)$ です。分母 $p_{11} - p_{10}$ を assignment span と呼びます。

### 説明

Yuragi-Striderのモデルには読み出し誤差が含まれていません。したがって実機側をこの式で補正しないと、モデルとの差の大部分が読み出し誤差で埋まってしまい、ダイナミクスの比較になりません。

校正回路を**同じジョブ内**に置くのは、読み出し特性が時間とともにドリフトするためです。別のジョブで取った校正値を使うと、ドリフトぶんが補正誤差として混入します。

### 検査方法

| 項目 | 実機側 | Yuragi-Strider側 | 対応 |
|---|---|---|---|
| 準備 0 | 何もせず測定 | 該当なし(補正のための実測値) | — |
| 準備 1 | $X$ ゲート後に測定 | 該当なし | — |
| ショット数 | 各 1,024 | — | — |
| 用途 | 全 $T_1$・Ramsey 点の補正 | 補正後の値をモデル予測と比較 | 同一ジョブ内の校正のみ使用 |

### 検査結果

| 測定量 | 実測値 |
|---|---|
| $p_{10} = P(\text{観測}1 \mid \text{準備}0)$ | 0.0048828125 |
| $p_{11} = P(\text{観測}1 \mid \text{準備}1)$ | 0.9873046875 |
| 分母 $p_{11} - p_{10}$ | 0.982421875 |

分母が 0.98 と 1 に近く、補正は十分に良条件です。以降のすべての実機値はこの補正を適用した後のものです。

## 3. $T_1$ 緩和

### 数式

実機データに当てはめるモデル関数と、Yuragi-Striderの参照曲線は次のとおりです。

$$
\text{実機フィット}:\quad P_1(t) = A\,e^{-t/T_1^{\text{fit}}}
\qquad
\text{モデル参照}:\quad P_1(t) = e^{-t/T_1^{\text{model}}}
$$

### 説明

$T_1$ は最も基本的なコヒーレンス指標であり、モデルの $\gamma_\downarrow$ に直接対応します。

比較の方向に注意が必要です。モデル参照値 $T_1^{\text{model}}$ は**デバイスの校正スナップショットに由来する値**であり、この測定から求めた値ではありません。したがってこの比較は「デバイスが公称する $T_1$ をモデルに入れたとき、同じデバイスの実測遅延曲線を再現できるか」という問いになります。

### 検査方法

| 項目 | 実機側 | Yuragi-Strider側 | 対応 |
|---|---|---|---|
| 回路 | $X \to \text{delay}(t) \to M$ | 同じ操作(励起状態から待機) | 論理的に同一 |
| 遅延点 | 0〜400 μs の21点 | 同じ21点 | 完全一致 |
| ショット | 各 1,024 | — | — |
| 入力パラメータ | デバイス自身の物性 | 校正スナップショット由来の $T_1^{\text{model}} = 303.33\ \mu\mathrm{s}$ | 実測校正値をモデルに入力 |
| 出力 | 読み出し補正後の $P(1)$ | $e^{-t/T_1^{\text{model}}}$ | 同一遅延点で比較 |
| 判定 | ブートストラップ95%信頼区間 | モデル曲線がその区間に入るか | 点ごとのカバー率で評価 |

### 検査結果

| 量 | 実機フィット | モデル参照値 |
|---|---|---|
| $T_1$ | **392.409 μs**(21点、振幅 0.97537、log-RMSE 0.029272) | 303.33 μs |

フィットの残差(log-RMSE 0.029)は小さく、実機データ自体は単一指数でよく記述されています。一方でフィット値はモデル参照値より約30%大きく、両者は一致していません。

## 4. Ramsey 振動

### 数式

Ramsey信号はコントラストとして扱います。

$$
C(t) = 1 - 2P_1^{\text{corr}}(t),
\qquad
C(t) = A\,e^{-t/T_2}\cos\left(2\pi f t + \phi\right)
$$

$T_1$ と $T_2$ から純位相緩和時間を導きます。

$$
\frac{1}{T_\phi} = \frac{1}{T_2} - \frac{1}{2T_1}
$$

### 説明

Ramseyは位相の緩和と、駆動周波数と量子ビット周波数の差(離調)の両方に感度を持ちます。振動周波数 $f$ が離調に対応します。

モデル側は離調を 0 として構成しているため、実機に振動が見えれば、その時点でモデルとの不一致が生じます。この項目の目的は、その不一致がどの程度で、離調として説明できるかを見ることです。

### 検査方法

| 項目 | 実機側 | Yuragi-Strider側 | 対応 |
|---|---|---|---|
| 回路 | $H \to \text{delay}(t) \to H \to M$ | 同じ操作 | 論理的に同一 |
| 遅延点 | 0〜400 μs の21点 | 同じ21点 | 完全一致 |
| 入力パラメータ | デバイス自身の物性 | 校正スナップショット由来の $T_2^{\text{model}} = 339.99\ \mu\mathrm{s}$ | 実測校正値をモデルに入力 |
| 出力 | 補正後のコントラスト | $A\,e^{-t/T_2^{\text{model}}}\cos(2\pi f t + \phi)$(振幅・位相・周波数は実機フィット値を流用) | 同一遅延点で比較 |

### 検査結果

| 量 | 実機フィット | モデル参照値 |
|---|---|---|
| $T_2$(Ramsey) | **437.616 μs**(振幅 0.96912、位相 0.00031 rad、RMSE 0.022887) | 339.99 μs |
| $T_\phi$(導出) | 989.189 μs | — |

Ramseyの振動周波数は 0.0067 cycles/μs でした。

:::note[周波数の単位について]
この値は **6.7 kHz** です。`cycles per μs` はそのまま MHz と等価です(1 cycle/μs = 1 MHz)。したがって

$$
0.0067\ \text{cycles}/\mathrm{\mu s} = 0.0067\ \mathrm{MHz} = \mathbf{6.7\ kHz}
$$

物理的にも kHz が整合します。遅延グリッドの間隔は 20 μs であり、Nyquist 限界は $1/(2\times20\ \mathrm{\mu s}) = 25$ kHz です。6.7 MHz(周期 0.15 μs)の振動はこのサンプリングでは激しくエイリアシングを起こし、観測された滑らかな振動としては現れません。6.7 kHz(周期 約149 μs)なら400 μsの窓におよそ2.7周期入り、フィット結果と整合します。
:::

## 5. ブートストラップによる判定

### 数式

各遅延点の観測カウントを二項分布から再標本化し、解析手順全体を繰り返して分布を作ります。$B$ 個のレプリカから 2.5% / 97.5% 分位点を取り、95%信頼区間とします。

$$
\text{カバー率} = \frac{1}{N}\sum_{i=1}^{N}
\mathbb{1}\!\left[\,L_i \le M(t_i) \le U_i\,\right]
$$

$[L_i, U_i]$ は遅延点 $t_i$ における信頼区間、$M(t_i)$ はモデル予測値です。

### 説明

「モデルと実機が合っているか」を目視ではなく統計的に判定するための手順です。読み出し校正も再標本化の対象に含めることで、校正の統計誤差も区間に反映されます。

判定基準を**測定前に**90%と定めているのが要点です。結果を見てから基準を決めれば、どんな結果でも合格にできてしまいます。

### 検査方法

```text
手法       : 決定論的二項ブートストラップ(同一ジョブ内の読み出し校正を含む)
レプリカ数 : 200
判定基準   : 各遅延点でのモデル点のカバー率が 90% 以上
```

### 検査結果

| 量 | 95% 信頼区間 | モデル点のカバー率 | 判定 |
|---|---|---|---|
| $T_1$ | 376.460 – 407.061 μs | **14.29%** | 不適合 |
| $T_2$ | 379.459 – 469.956 μs | **57.14%** | 不適合 |

PASS基準は 90% です。$T_1$ は 14.29%、$T_2$ は 57.14% であり、いずれも大きく下回りました。

**判定: 候補段階(形式監査には昇格せず)**

| 項目 | 状態 |
|---|---|
| 形式監査の資格 | なし |
| プロトコルの実行前確定 | なし |
| モデルの再フィット | 行っていない |

**未達成の理由は2つあります。**

1. **プロトコルの事前登録が実行前に確定していなかった**ため、形式的な監査に昇格できない(手続き上の理由)
2. **モデル点のカバー率が基準を満たしていない**(統計的な理由)

なお、モデルの再フィットは行っていません。実機に合わせてパラメータを調整すれば見かけ上の一致は改善しますが、それは予測能力の検証にならないためです。

## 6. 再現性

### 数式

同一条件の測定を2回実行し、フィット値のばらつきを見ます。

$$
\frac{\left|f_2 - f_1\right|}{f_1}
$$

### 説明

1回の測定でモデルと合わないとき、原因は「モデルが違う」か「実機の値が安定していない」かのどちらかです。両者を区別するには、同じ測定を独立に繰り返すしかありません。

### 検査方法

同じRamsey測定(21点)を、約10時間の間隔をあけて2回実行しました。

### 検査結果

| 実行 | ジョブID | 日時 | 周波数 | $T_2$ | RMSE |
|---|---|---|---|---|---|
| 1回目 | `d9nl3d6ij12s73fu19kg` | 2026-08-02 22:30 | **6.80 kHz** | 390.4 μs | 0.0355 |
| 2回目 | `d9ntoj460llc73cagtgg` | 2026-08-03 08:48 | **9.55 kHz** | 443.9 μs | 0.0380 |

:::warning[周波数が約40%変動]
フィットされた周波数は 2.75 kHz(約40%)変化しました。

これは「定性的には再現するが、定量的には周波数が不安定」であることを意味します。**特定の離調値を安定した物理量として確立することはできていません。**
:::

さらに、1回目の実行では単一トーンフィットの候補RMSEが 0.03546 / 0.03554 / 0.03558 / 0.03573 と極めて接近しており、**周波数が良く決まっていない**(識別性が低い)ことが記録されています。21点の実行では識別性が改善しましたが、周波数そのものの信頼区間は算出しておらず、探索的なフィットにとどまります。

## 7. スピンエコー

### 数式

エコー系列は、待機の中央に $X$ を挟むことで準静的な離調をリフォーカスします。

$$
\phi_{\text{total}} = \delta\cdot\frac{t}{2} - \delta\cdot\frac{t}{2} = 0
$$

$\delta$ が測定中に変化しなければ、位相の蓄積は打ち消されます。

### 説明

Ramseyで見えた 6.8〜9.55 kHz の振動が**準静的な離調**によるものなら、エコーでは消えるはずです。逆にエコーでも残るなら、原因は別にあります。

### 検査方法

```text
ジョブID : d9o12h8qs0bc73e3v590
測定     : 21点 × 256ショット = 5,888
回路     : H → delay(t/2) → X → delay(t/2) → H → M
```

### 検査結果

```text
周波数 : 0.05 kHz
T2     : 374.086 μs
RMSE   : 0.038613
```

Ramseyで見えた振動は**回復されませんでした**。これは準静的な離調がエコーによってリフォーカスされたという解釈と矛盾しませんが、それを証明するものではありません。

:::warning[フィットが悪条件です]
フィット振幅が **3.2194** と非物理的な値(振幅は1以下であるべき)になっており、この条件ではフィット自体が良く決まっていません。周波数 0.05 kHz という値も、そのような悪条件のフィットから出たものとして扱う必要があります。
:::

## 8. ネイティブゲートモデルとの直接比較

### 数式

ここまでの比較がフィット値どうしの突き合わせだったのに対し、この項目では**Yuragi-Striderで実際に回路を時間発展させ**、遅延点ごとの $P(1)$ を実機と直接比較します。

IBMのネイティブゲートをモデル上で構成します。

$$
\text{SX} = R_X(\pi/2),
\qquad
X = R_X(\pi),
\qquad
H = R_Z(\pi/2)\cdot R_X(\pi/2)\cdot R_Z(\pi/2)
$$

$R_Z$ は仮想ゲートとして所要時間 0、$R_X$ は実機のSXゲート長 32 ns を所要時間とします。待機区間には離調に相当するハミルトニアンを置けます。

$$
H_{\text{idle}} = \frac{2\pi f_{\text{det}}}{2}\,\sigma_z
$$

### 説明

前項までの比較では、モデル側は解析的な減衰曲線でした。この項目では Gate-aware CPTP 経路で回路そのものを発展させるため、ゲート実行中のデコヒーレンスや $H$ の分解まで含めた比較になります。

離調の走査は「どの離調値を仮定すれば実機のRamsey信号を最もよく説明できるか」を見る診断であり、モデルの変更ではありません。

### 検査方法

**入力の対応**

| 項目 | 実機側 | Yuragi-Strider側 | 対応 |
|---|---|---|---|
| 回路(T1) | 転送後の $X \to \text{delay} \to M$ | $R_X(\pi)$(所要 32 ns)→ 待機区間 | ネイティブゲートに合わせて構成 |
| 回路(Ramsey) | 転送後の $H \to \text{delay} \to H \to M$、$H$ は SX と RZ に分解済み | $R_Z(\pi/2)\cdot R_X(\pi/2)\cdot R_Z(\pi/2)$、$R_X$ のみ 32 ns、$R_Z$ は 0 ns | 実機の仮想Z実装に合わせる |
| 遅延 | dt 単位の `delay`(21点) | 同じ長さの待機区間(21点) | 数値として同一 |
| コヒーレンス時間 | ランタイム取得の校正値 $T_1 = 300.161$ μs、$T_2 = 315.270$ μs | 同じ値を入力に代入($T_1$(0 K)$= T_1$、$T_\phi$ は導出値、15 mK、5 GHz。比較の当時は品質 1.0・磁束ノイズ 0 で、2026-11-14以降の直接入力と同じ率) | **実機の校正値をモデル入力に写す** |
| ゲート長 | 校正値 SX = 32 ns、RZ = 0 ns | 同じ値を所要時間に指定 | 数値として同一 |
| 読み出し | 実測カウント | モデルに読み出し誤差なし | 実機側をアフィン補正 |
| 比較量 | 補正後の $P(1)$ | $\rho_{11}$ | 同一遅延点で1対1 |
| 離調 | 制御していない | 0 を既定とし、0〜10 kHz を 0.1 kHz 刻みで走査 | 走査は診断であり、モデルの既定値は 0 |

換算された環境レート:

| 量 | 値 |
|---|---|
| 実効 $T_1$ | 300.161 μs |
| 実効 $T_2$ | 315.270 μs |
| 実効 $T_\phi$ | 663.960 μs |
| $\gamma_\downarrow$ | 3.3315e-3 μs⁻¹ |
| $\gamma_\uparrow$ | 3.7586e-10 μs⁻¹ |
| $\gamma_\phi$ | 1.5061e-3 μs⁻¹ |

### 検査結果

| 実験 | 最大差 | 平均差 |
|---|---|---|
| $T_1$ | 0.10772 | 0.05905 |
| Ramsey | **0.76367** | **0.28990** |

$T_1$ 系列は最大でも 0.11 の差に収まる一方、Ramsey系列の不一致が際立って大きいことがわかります。モデル側に振動がないためです。

離調を 0 から 10 kHz まで 0.1 kHz 刻みで走査した結果:

| 条件 | RMSE |
|---|---|
| 離調ゼロ | 0.374244 |
| 最良(6.7 kHz) | **0.030026** |

離調を導入するとRMSEが1桁改善します。ただし前述のとおり、この 6.7 kHz という値は独立実行では 9.55 kHz に変動しており、安定したパラメータではありません。

この比較には次の制限があります。

- SXは大域位相を除いて $R_X(\pi/2)$ として表現しており、パルス形状は再現していない
- RZ は所要時間 0 の仮想ゲートとして扱っている
- 読み出しは補正しているが、ネイティブゲート固有の誤差チャネルは別途挿入していない

## 9. 校正ドリフト説の検証

### 数式

比較に用いるモデル参照値を、古い校正スナップショットから新しいものへ差し替え、カバー率の変化を見ます。

### 説明

「モデル参照値が古い校正に基づくため一致しないのではないか」という仮説は、もっともらしく、かつ検証可能です。新しい校正値で改善するなら不一致はドリフトで説明でき、改善しないなら別の原因を探す必要があります。

### 検査方法

同じ実機データ(ジョブ `d9nlh5ssfqic73ar6f30`)に対して、モデル参照値だけを差し替えて再解析します。新しいスナップショットは 2026-08-03 08:28:25 JST にランタイムから取得したものです。

### 検査結果

| 校正スナップショット | $T_1$ | $T_2$ | $T_1$カバー率 | $T_2$カバー率 |
|---|---|---|---|---|
| 旧(2026-07-30 取得) | 303.33 μs | 339.99 μs | 14.3% | 57.1% |
| 新(2026-08-03 取得) | 300.161 μs | 315.270 μs | 14.3% | **47.6%** |

**カバー率は改善しませんでした**($T_2$ はむしろ悪化)。したがって不一致は校正ドリフトでは説明できません。

新しいスナップショットの詳細:

| 項目 | 値 |
|---|---|
| SX / X ゲート長 | 32 ns |
| RZ ゲート長 | 0 ns(仮想ゲート) |
| 読み出し誤差 | 0.00708 |
| $P(\text{観測}0 \mid \text{準備}1)$ | 0.007568 |
| $P(\text{観測}1 \mid \text{準備}0)$ | 0.006592 |
| 読み出しに要する時間 | 2180 ns |
| 転送後の命令数 | measure 44、x 22、delay 42、rz 84、sx 42 |

:::note[参照値は2系統あります]
本ページには $T_1$/$T_2$ の参照値が2組(303.33 / 339.99 と 300.161 / 315.270)登場します。どちらも同じ量子ビットの校正値ですが、取得時刻が異なります。数値を引用する際は、どちらのスナップショットに基づくかを必ず確認してください。
:::

# Gate-awareモデル

Gate-awareモデルは、論理的な量子ゲートに**有限の所要時間**を与え、その時間のあいだ環境ノイズが作用するものとして扱う制御モデルです。Yuragi-Striderの既定の制御モデルです。

理想的な量子回路シミュレーターがゲートを瞬時の行列演算として扱うのに対し、Gate-awareモデルはゲート実行中のデコヒーレンスを表現します。これにより「回路が長くなるほど、またゲートが遅いほど劣化する」という因果関係が可視化されます。

## はじめに — 「ゲートに時間がある」とはどういうことか

:::info[この節は前提知識なしで読めます]
量子回路シミュレーターに触れるのが初めての場合、まずここだけ読めば Gate-awareモデルが何をするものか掴めます。以降の節は仕様の記述です。
:::

### 量子ゲートとは

**量子回路**は、量子ビットに対して操作を順番に掛けていく手順書です。その操作ひとつひとつを**ゲート**と呼びます。ビットを反転させる X、重ね合わせを作る H、2つの量子ビットを絡ませる CNOT などがあり、数学的にはどれもユニタリ行列 $U$ です。

教科書どおりの量子回路シミュレーターは、状態にこの行列を掛けるだけです。行列の掛け算に時間の概念はないので、**回路をどれだけ長くしても結果は理想のまま**です。

### 実機ではゲートは物理過程である

しかし実機では、ゲートは瞬時の行列演算ではありません。X ゲートは「量子ビットの共鳴周波数に合わせたマイクロ波を、決まった時間だけ照射する」という物理過程で、必ず有限の時間がかかります。おおよそ1量子ビットゲートで数十 ns、2量子ビットゲートはその10倍程度です。

そしてその時間のあいだ、量子ビットは環境と繋がったままです。エネルギーは緩和($T_1$)し、位相は乱れ($T_2$)ます。**これらは時計に従って進むので、回路が長いほど、そして遅いゲートを使うほど、結果は劣化します。**

### Gate-awareモデルがすること

Gate-awareモデルは、この落差を埋めるために、各ゲートに**所要時間 $\tau$ を持たせます**。そしてその $\tau$ のあいだ、「望みのユニタリ $U$ を起こすハミルトニアン」と「環境による散逸」を**同時に**走らせます。

```text
理想シミュレーター
  |ψ⟩ ──[H]──[CNOT]──[X]──▶            時間軸が存在しない

Gate-awareモデル
   ρ  ──[ H ]──[   CNOT   ]──[ X ]──▶  t
        0.02μs     0.20μs     0.02μs
        └────── この間ずっと T1 / T2 が効く ──────┘
```

たとえば CNOT は既定で X の10倍の時間がかかるので、CNOT をひとつ足すことは、環境に晒される時間の面では X を10個足すのと同じです。「アルゴリズムを2量子ビットゲートの少ない形に書き直すと結果が良くなる」といった、実機で当たり前に起きることが、そのまま再現されます。

### このモデルが**しない**こと

| | Gate-aware | [Pulse-level](./pulse-levelmodel.md) |
|---|---|---|
| 制御の記述 | ゲート名と所要時間 | マイクロ波の波形そのもの |
| ゲートの正確さ | **理想のユニタリを厳密に実現すると仮定** | 波形しだいで誤差が出る |
| 第3準位($\lvert 2\rangle$)への漏れ | 扱わない | 扱う |
| 劣化の原因 | 環境ノイズのみ | 環境ノイズ + 制御誤差 + 漏れ |
| 扱える規模 | 最大18量子ビット(ノイズありは8) | 1〜4台のトランズモン |

つまり Gate-aware は「**制御は完璧、悪いのは環境だけ**」という設定です。較正誤差やパルス歪みは含まれないため、ここで出る劣化は**実機の下限**と考えてください。制御そのものの誤差まで見たい場合は Pulse-levelモデルを使います。

この割り切りの見返りとして計算が軽く、パルス波形を刻む必要がないため、十数量子ビットの回路を現実的な時間で扱えます。

## 基本的な考え方

```text
回路 → ゲート列(column)に分解
      → 各列のユニタリ U_k と所要時間 τ_k を決定
      → 有効ハミルトニアン H_k を逆算
      → その区間を H_k と散逸子で時間発展
```

同じ列に置かれた複数のゲートは、同一の時間区間で同時に作用します。列の所要時間は、その列に含まれるゲートの所要時間の最大値です。

## サポートするゲート

19種類のゲートが利用できます。

```text
I, H, X, Y, Z, S, T, RX, RY, RZ, CNOT, CZ, CP, CCX, SWAP, QFT, ORACLE, MEASURE, MESSAGE
```

ネイティブゲート集合の識別子は `gate_aware_hxyzst_rz_cnot_v3` です。

QFT だけはオペランド数が可変で、制御を取らず、レジスタ全体を `targets` に最上位ビットから並べます。またがる量子ビットは連続していなくても昇順でなくてもかまいません。`targets` の順序はユニタリを変えるため、`[0,1]` と `[1,0]` は異なるゲートです。

回路エディタ側はレジスタをビット0(最下位)から入力するため、上から順にクリックすると Quirk や Qiskit と同じオペランド順になります。盤面の数字はビット重み $k$(その量子ビットが $2^k$ を担う)です。

ORACLE も同じレジスタ規約の可変幅ゲートで、`params.marked_index` が指す1つの計算基底状態の位相だけを反転します($O=I-2\lvert m\rangle\langle m\rvert$)。対角の $\pm1$ 行列なのでエルミートかつ対合で、有効ハミルトニアンは対合経路をそのまま使います。Grover の拡散演算子は $-H^{\otimes n}\,O_{\lvert0\cdots0\rangle}\,H^{\otimes n}$ と書けるため、**H と ORACLE の2種類だけで Grover 探索全体が構成できます**。盤面の数字は、マークする状態がその量子ビットに要求するビットです。

## 既定のゲート所要時間

| ゲート | 所要時間 [μs] | 分類 |
|---|---|---|
| I | 0.0 | 恒等 |
| H, X, Y | 0.02 | 1量子ビット回転 |
| RX, RY, RZ | 0.02 | 1量子ビット回転 |
| Z, S, T | 0.0 | 仮想位相ゲート |
| CNOT, CZ, SWAP, CP | 0.20 | 2量子ビット |
| CCX | 0.40 | 3量子ビット |
| QFT | 0.20 × またぐ量子ビット数 | 可変幅 |
| ORACLE | 0.20 × またぐ量子ビット数 | 可変幅 |
| MEASURE | 0.0 | 測定 |
| MESSAGE | 0.04 | 古典通信 |

Z, S, T の所要時間が 0 なのは、これらがフレーム更新(仮想位相ゲート)として実装される想定だからです。実機でも仮想Zゲートは時間を消費しません。

所要時間はゲートごとに `params.duration_us` で個別に上書きできます。

## 有効ハミルトニアンの構成

ゲートのユニタリ $U_k$ と所要時間 $\tau_k$ から、$e^{-iH_k\tau_k} = U_k$ を満たす $H_k$ を求めます。実装は2つの経路を持ちます。

| 条件 | 経路 | 式 |
|---|---|---|
| $U^\dagger \approx U$ かつ $U^2 \approx I$ | 対合 | $H_k = \dfrac{\pi}{2\tau_k}(I - U_k)$ |
| それ以外 | スペクトル生成子 | $H_k = V\operatorname{diag}(-\theta_j/\tau_k)V^{-1}$ |

判定の許容誤差は $10^{-9}$、スペクトル経路の再構成検証は $5\times10^{-9}$ です。詳細は[Lindblad方程式](../lindblad.md)を参照してください。

スペクトル経路が再構成検証に落ちる場合だけ、正規行列向けの経路へ切り替えます。QFT のように固有値が縮退するゲートでは、一般固有値ソルバが縮退固有空間内で非直交な基底を返すことがあり、そこから作った生成子は Hermite 化すると元のユニタリを再現しません。ユニタリは正規行列なので Hermite 部と反 Hermite 部が可換であり、`eigh` を2段適用すれば厳密に直交な固有基底が得られます。

宣言されているモード識別子は `effective_unitary_spectral_generator_v2` で、対合互換の分岐を含みます。

## ゲート分解モード

| モード | 動作 |
|---|---|
| `logical_direct`(既定) | 論理ゲートをそのまま有効ハミルトニアンに変換 |
| `auto_decompose` | ネイティブゲート集合に分解してから変換 |

分解可能なゲートと規則は次のとおりです。

| ゲート | 規則ID | 分解 |
|---|---|---|
| RX | `rx_to_h_rz_h_v1` | H · RZ · H |
| RY | `ry_to_rz_h_rz_h_rz_v1` | RZ(−π/2) · H · RZ(θ) · H · RZ(π/2) |
| CZ | `cz_to_h_cnot_h_v1` | H · CNOT · H |
| SWAP | `swap_to_three_cnot_v1` | CNOT × 3 |
| CP | `cp_to_rz_cnot_v1` | RZ と CNOT |
| CCX | `ccx_to_h_cnot_rz_v1` | 15操作・13層 |
| QFT | `qft_to_h_cp_swap_v1` | H・CP 梯子 + ビット反転SWAP |
| ORACLE | `oracle_to_x_mcz_graycode_v1` | X + 多重制御Z(グレイコード順の CNOT・RZ) |

QFT の分解が出す CP と SWAP はそれ自体が分解可能なので、コンパイラはさらに既存規則へ再帰的に展開します。したがって分解後回路に現れるのは H・RZ・CNOT だけで、ネイティブゲート集合は拡張されていません。

:::note[大域位相について]
CP の分解は元のゲートと大域位相 $e^{-i\theta/4}$ だけ異なります。CCX の分解結果は $e^{-i\pi/8}\cdot\mathrm{CCX}$ になります。QFT は各 CP の位相が積み上がった大域位相を持ちます。大域位相は観測量に影響しませんが、密度行列を直接比較する場合は注意が必要です。
:::

分解モードを使うと、同じ論理回路でも時間区間の数と総所要時間が変わるため、デコヒーレンスの量も変わります。これは実機でネイティブゲートに分解した場合の挙動に対応します。

## 測定モデル

MEASURE は**非選択的な射影チャネル**として実装されます。

- 測定結果は破棄され、状態は測定基底で対角化される
- 読み出し判別誤差は、射影後の終端観測に独立なアフィン2点近似として任意で適用できる
- 所要時間は既定で 0

測定結果を古典レジスタに保持し、後続のゲートを条件付きで実行する**フィードフォワード**も利用できます。この場合、分岐ごとに別々のノイズあり時間発展が計算されます。

| 項目 | 値 |
|---|---|
| 古典分岐の上限 | 4096 |
| 上限超過時の挙動 | 切り捨てず例外 |
| 分岐モード識別子 | `gate_aware_noisy_branching_v1`(密度行列)/ `statevector_branching_v1` |

APIは監査用のプリセットとして `bell`、`teleportation`、`bit_flip_repetition` を受け付けます。後者2つは古典レジスタと条件付き補正を含みます。

## ビット順の規約

基底ラベルは **q0 が最上位ビット** です。2量子ビットの状態 `"01"` は q0 = 0、q1 = 1 を意味します。

## 規模の上限

```text
最大論理量子ビット数        : 18
密度行列(ノイズあり)の上限  : 8
```

9量子ビット以上でノイズを含む計算は拒否されます。理想環境かつ測定なしの場合のみ[状態ベクトル経路](../propagation/statevector.md)で18量子ビットまで実行できます。

## 検証状況

Gate-awareモデルは次のように検証されています。

- ゼロ散逸極限で独立に構成したユニタリ発展と一致(V1、最大誤差 $1.11\times10^{-16}$)
- QuTiPとの独立比較(V7、7ケース、最大誤差 $2.10\times10^{-10}$)
- 明示的CPTP経路の凍結(`yuragi_strider_gate_aware_cptp_v1`、PASS WITH RESTRICTIONS)

詳細は[制御モデルの検証](../validations/control-models.md)を参照してください。

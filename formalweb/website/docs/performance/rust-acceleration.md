# Rustによる高速化

Yuragi-Striderには、ノイズを含む密度行列シミュレーションの重い反復計算をRustで実行する、**任意の高速化経路**があります。物理モデルや時間刻みを簡略化して速くするのではなく、標準のPython/NumPy経路と同じ方程式・同じ固定ステップを、コンパイル済みの計算処理で進めます。

2026年8月14日の同一PC上の測定では、代表的な1〜5量子ビット回路のシミュレーション全体が、標準経路に対して **2.96〜7.26倍**高速になりました。倍率は回路、量子ビット数、待機時間、出力点数によって変わります。

本ページの表は、この1〜5量子ビットの代表回路だけを対象としています。6〜8量子ビットについては測定回数を減らした参考測定を[別の節](#large-qubit-reference)にまとめており、こちらは表とは条件も精度も異なります。

:::info[現在は任意の高速化機能です]
標準経路は引き続きPython/NumPyです。Rust実行環境がない場合や高速化処理を利用できない場合も、同じ入力を標準経路で計算できます。実際にどちらで実行されたかは結果の診断情報で確認できます。
:::

## 何を計算しているか

ノイズを含む回路では、状態ベクトルではなく密度行列 $\rho$ を使い、Lindblad方程式を解きます。

$$
\frac{d\rho}{dt}
= -i[H,\rho]
+ \sum_k \left(
L_k\rho L_k^\dagger
- \frac{1}{2}\{L_k^\dagger L_k,\rho\}
\right)
$$

時間発展には固定ステップの4次Runge-Kutta法を用います。1ステップごとに右辺を4回評価するため、量子ビット数、ノイズ項、内部ステップ数が増えるほど、複素行列の積が計算時間の中心になります。

Rust経路は、このうち次の処理を担当します。

1. ハミルトニアンと散逸を含むLindblad方程式の右辺評価
2. 4段のRunge-Kutta計算
3. 各ステップ後のHermite性とトレースの数値補正
4. 複数ステップの連続実行と、指定された観測時刻の状態の返却

Python側は、回路と環境条件からハミルトニアンや散逸率を組み立て、時間区間を計画し、Rustから返された状態を忠実度・純度などの表示値へ変換します。

## なぜ速くなるか

標準経路でも行列演算そのものにはNumPyを使いますが、時間ステップを進めるたびにPython側の制御処理が入ります。Rust経路では、連続する複数ステップを一度に渡し、その区間をコンパイル済み処理の中で完結させます。

これにより、主に次の費用が減ります。

- 時間ステップごとのPython関数呼び出し
- Pythonとコンパイル済み処理の間を往復する回数
- 中間状態をPythonオブジェクトへ変換する回数
- 散逸演算子と状態を区間ごとに変換・コピーする回数
- ノイズあり軌跡と理想軌跡で同じ区間情報を二重に変換する費用
- 観測点ごとに純度やトレース誤差をPython側で再計算する費用
- 行列積ごとの一時メモリ確保
- 局所的な散逸演算子をゼロ要素まで含む密行列として掛ける費用
- 小さな複素行列を繰り返し操作する際の制御オーバーヘッド

ただし、計算量の次数そのものは変わりません。$n$量子ビットでは密度行列が $2^n \times 2^n$ となり、主要な密行列積はおおむね $O(8^n)$ で増加します。Rustは定数倍と固定費を改善しますが、大規模量子系を扱える方式へ変えるものではありません。

## 実装している最適化

上記の費用を減らすために、Rust経路では次の処理をまとめています。

**準備の使い回し**

散逸演算子から作られる共役転置と積は、時間発展中に変化しません。計算セッションの開始時に一度だけ準備し、回路区間をまたいで再利用します。状態もRust側に保持し、Python側で測定や瞬時ゲートによる変更がなければ再送しません。Runge-Kuttaの各段で使う微分、途中状態、行列積の作業領域も固定バッファとして再利用します。同じ実行スレッドで環境条件が一致する反復計算では、準備済みの計算セッションごと再利用します。状態は実行ごとに同期するため、前回の結果が次回へ混ざることはありません。

**言語間で渡すデータの削減**

Pythonから巨大なノイズ演算子を渡さず、量子ビット数と緩和・励起・位相緩和のレートだけを渡します。Rust側は局所的な疎構造を直接組み立てるため、ゼロ要素を含む密行列の生成と積を避けられます。回路中のハミルトニアンは一度だけ登録し、時間発展中は短い識別子で参照するので、同じゲート区間を繰り返すたびに行列を変換し直す必要がありません。複数の異なるハミルトニアン区間も一度の呼び出しで処理でき、各区間末の状態だけを返せます。

**疎構造の利用**

散逸演算子やハミルトニアンの非ゼロ要素が少ない場合は、その位置と値だけを使う構造化計算へ自動的に切り替えます。6〜8量子ビットの固定ステップRK4では、局所ゲートから得られるゼロ要素の多いハミルトニアンも疎構造として登録し、交換子の計算は非ゼロ要素だけを走査します。また、待機区間などハミルトニアンがゼロのときは、値が必ずゼロになる交換子の行列積を実行しません。忠実度や純度に現れる $\operatorname{Tr}(AB)$ も、行列積全体を作らず対応要素の積和として評価します。

**戻り値の削減**

測定や古典条件分岐を含まない連続区間では、ノイズあり状態と理想状態を別々に往復させません。両方の軌跡、複数の観測点、純度、トレース誤差、および純粋な理想状態に対する忠実度を、一度のRust呼び出しでまとめて計算します。Pythonへ戻す密度行列は、最終状態など実際に必要なものに限定します。途中状態を表示する場合も、画面から要求された時刻だけを選んで復元します。理想状態が数値的に混合状態と判定される点では、従来と同じUhlmann忠実度をPython側で評価します。

**既知ゲートに対する再検証の省略**

実効ハミルトニアン $H = \frac{\pi}{2\tau}(I - U)$ を作る経路では、通常 $U^\dagger = U$ と $U^2 = I$ を密行列で検証します。この検証は、`I`、`H`、`X`、`Y`、`Z`、`CNOT`、`CZ`、`SWAP`、`CCX`、`ORACLE` だけで構成され、かつ作用先が重ならない列に限って省略します。これらの行列は利用者の入力ではなくYuragi-Strider内部で構成しており、Hermiteかつ対合であることが定義から保証されているためです。この条件から外れる列、たとえば回転ゲートや一般のユニタリを含む列は、これまでどおり完全な検証を通ります。

## 回路別の実測結果

下表は、忠実度や純度などの結果系列の生成を含むシミュレーション全体の経過時間です。各経路を3回ウォームアップした後、実行順を入れ替えながら11回測定し、中央値を比較しました。RustからPythonへの切り替えが起きていないことも各回で確認しています。

| 回路 | 条件 | 想定ユースケース | Python/NumPy | Rust | 高速化 |
|---|---|---|---:|---:|---:|
| 1量子ビット H | 全体 1.00 µs、51出力点 | 初学者向けの単一ゲート確認 | 12.458 ms | 2.040 ms | **6.11倍** |
| 2量子ビット Bell | H＋CNOT 0.20 µs、全体 1.00 µs、41出力点 | もつれとノイズの比較 | 18.946 ms | 3.763 ms | **5.03倍** |
| 2量子ビット Bell、長いCNOT | CNOT 20.0 µs、全体 20.02 µs、41出力点 | ゲート時間の影響確認 | 19.443 ms | 2.766 ms | **7.03倍** |
| 3量子ビット GHZ型 | H＋CNOT 2個、全体 1.00 µs、21出力点 | 小規模な多量子ビット探索 | 28.030 ms | 8.789 ms | **3.19倍** |
| 4量子ビット、独立Bell対 | H＋CNOTを2組、全体 0.80 µs、21出力点 | 複数部分回路の比較 | 53.136 ms | 17.979 ms | **2.96倍** |
| 5量子ビット H | 全体 0.02 µs、3出力点 | 密度行列32×32での境界確認 | 103.815 ms | 14.301 ms | **7.26倍** |

各行は所要時間、出力点数、ゲート構成がそれぞれ異なるため、行どうしを直接比べて「量子ビット数が増えると倍率がこうなる」と読むことはできません。たとえば5量子ビットの行は全体 0.02 µs・3出力点と非常に短く、4量子ビットの行より積分ステップ数が少なくなっています。

### 共通の測定条件

| 項目 | 条件 |
|---|---|
| 実行環境 | Windows 11、12th Gen Intel Core i5-1235U |
| 数値環境 | Python 3.14.4、NumPy 2.4.4 |
| 初期状態 | 全量子ビット $|0\rangle$ |
| 温度 | 0 mK |
| 量子ビット周波数 | 5.0 GHz |
| $T_1$(0 K)・$T_\phi$ | それぞれ 10 µs |
| ゲート時間 | 既定値（H 0.02 µs、CNOT 0.20 µs）。長いCNOTの行のみ上書き |
| 比較対象 | 同じ入力、同じ時間格子、同じRK4ステップ規則、同じ出力生成 |

これらは特定のPCでの小規模ベンチマークであり、別のCPU、負荷状態、回路、出力点数では絶対時間と倍率が変わります。特に短い計算では、入力検証や結果整形など共通処理の割合が大きいため、Rust部分だけの速度を表す値ではありません。

## 6〜8量子ビットでの参考測定 \{#large-qubit-reference}

以下は**参考値**です。1回あたりの実行時間が長く、「回路別の実測結果」と同じ11回測定を行っていないため、あちらとは別の精度で扱ってください。条件は短時間の単一Hゲート、ノイズあり、3観測点です。

| 回路 | 測定回数 | Python/NumPy | Rust | 高速化 |
|---|---:|---:|---:|---:|
| 6量子ビット H | 5回中央値 | 0.761 秒 | 0.039 秒 | 約19.4倍 |
| 7量子ビット H | 5回中央値 | 7.355 秒 | 0.285 秒 | 約25.8倍 |
| 8量子ビット H | 3回中央値 | 142.19 秒 | 4.544 秒 | 約31.3倍 |

この領域では、疎構造の利用と言語間データ変換の削減が特に効くため、上表の1〜5量子ビットより倍率が大きく出ます。ただし密度行列の指数的な増加そのものは残ります。この3行では量子ビットを1つ増やすたびにRust経路でも所要時間が7〜16倍になり、8量子ビットでは $256\times256$ の密度行列を扱うため、Rustでも1回の実行に4.5秒かかります。倍率が大きいことは、この指数的な壁がなくなったことを意味しません。測定時の負荷による変動も大きく、保証値ではありません。

これらの値は次のように再現できます。

```bash
python scripts/benchmark_rust_dense.py --only 6qubit-h,7qubit-h --warmups 2 --repeats 5
python scripts/benchmark_rust_dense.py --only 8qubit-h --warmups 1 --repeats 3
```

## どの用途で効果があるか

Rust経路は、次のような**同じ種類の小規模シミュレーションを何度も行う用途**で効果を感じやすくなります。

- 温度や緩和時間を変えながら結果を比較する
- CNOT時間や待機時間を変えて劣化の原因を調べる
- 画面上の入力を動かし、結果を繰り返し更新する
- 1〜3量子ビットの回路候補を多数試す
- パルス形状やデチューニングの候補を小さな範囲で走査する

一方、理想条件で状態ベクトル経路が選ばれる大きな回路、ファイル入出力が支配的な処理、1回だけの非常に短い計算では、Rust経路の利点は小さくなることがあります。

## 結果は変わらないか

高速化経路は、標準経路と同じ物理入力、時間格子、RK4式、密度行列の補正規則を使用します。「回路別の実測結果」の6条件について両経路の出力を比較した結果は次のとおりです。

| 比較した量 | 標準経路との最大絶対差 |
|---|---:|
| 純度の系列 | $1.22\times10^{-15}$ |
| 忠実度の系列（純粋な理想状態に対する点） | $4.44\times10^{-16}$ |
| 忠実度の系列（Uhlmann式を使う点） | $2.72\times10^{-8}$ |

純度が倍精度の丸め誤差の水準で一致することは、両経路が同じ密度行列に到達していることを示します。この比較は次のコマンドで再現できます。

```bash
python scripts/benchmark_rust_dense.py --parity
```

忠実度だけ大きく見えるのは、経路が食い違っているためではありません。理想側の軌跡もRK4で積分するため、点によっては理想状態の純度が数値的に1からわずかに外れ、そのときは両経路とも共通のUhlmann忠実度

$$
F(\rho,\sigma) = \left(
\operatorname{Tr}\sqrt{\sqrt{\sigma}\,\rho\,\sqrt{\sigma}}
\right)^2
$$

をPython側で評価します。この式はほぼゼロの固有値の平方根を取るため、入力の $10^{-16}$ 程度の違いが出力では $10^{-8}$ 程度に拡大されます。$\sqrt{10^{-16}} = 10^{-8}$ という関係がそのまま現れているだけで、Uhlmann式に固有の条件数の問題です。今回の測定では、2量子ビットBellで41点中7点、3量子ビットGHZ型で21点中8点がこの経路に入りました。純粋な理想状態に対して $\operatorname{Tr}(\rho\sigma)$ を評価する残りの点では、忠実度も丸め誤差の水準で一致します。

また、Rust側で処理できない場合は標準経路へ切り替え、その事実を診断情報に残します。高速化を要求したという設定だけでなく、**実際にRustで計算されたことを確認してから性能を比較する**のが重要です。

数値積分そのものの精度、収束性、CPTPに関する制約は高速化の有無で変わりません。詳しくは[RK4(固定ステップ数値積分)](../physics-model/propagation/RK4.md)と[時間発展の検証](../physics-model/validations/propagation.md)を参照してください。

## まとめ

Rustによる高速化は、物理モデルを簡略化する近道ではなく、同じ密度行列計算を少ない言語間往復と少ないメモリ確保で実行するための選択肢です。1〜5量子ビットの代表条件では **2.96〜7.26倍**の短縮が確認され、疎構造の利用が効く6〜8量子ビットの参考測定ではさらに大きな倍率になりました。最も適した用途は、少数量子ビットのノイズあり回路を対話的に比較したり、条件を変えて反復実行したりする場面です。
